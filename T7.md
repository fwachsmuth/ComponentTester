# Blue-PCB T7 investigation

This board is separate from the working TC1. Do not apply the TC1's STC15
power-controller HEX to it. The U5 photograph appears to read STC8G1K08,
possibly with an A suffix on the following line. Bootloader identification has
now confirmed **STC8G1K08-8PIN, F7A4**, without the A suffix. Its factory firmware
was subsequently replaced by the experimental R1 controller firmware.

## Verified by measurement

All voltages were reported relative to battery negative, with no USB or ISP.
Readings were taken at different times and are not necessarily simultaneous.

The physical button reaches U5 and the controller-to-AVR signal paths match
the TC1 replacement firmware. A meter does not exclude short pulses on PD1;
the factory U5 protocol has not been established.

## Replacement firmware reference

Source: https://github.com/atar-axis/tc1-u4/blob/master/tc1-u4/main.c

The STC15 reference forwards a debounced button level to AVR PD1, enables
the converter, waits for a high level on AVR PD2, and removes power when
PD2 goes low. This describes the replacement, not the unknown factory code.

STC8G SOP8 manufacturer pinout:
https://www.stcmicro.com/datasheet/STC8G1K08_Features.pdf (page 12)

| Pin | STC8G signal | Board function |
| --- | --- | --- |
| 1 | P5.4 | Button input, observed |
| 2 | VCC | Supply, observed |
| 3 | P5.5 | Active-high power-enable candidate; off/on levels match, converter connection not traced |
| 4 | GND | Datasheet ground; board connection not yet checked |
| 5 | P3.0 | UART RX, board use unverified |
| 6 | P3.1 | UART TX, board use unverified |
| 7 | P3.2 | ATmega PD1, continuity verified |
| 8 | P3.3 | ATmega PD2, continuity verified |

A source port requires GPIO mapping/modes, timer and wake-up configuration,
and compiler syntax changes. SDCC supports 8051; Keil is not mandatory.
An experimental SDCC implementation has now been built and host-tested in
[power-controller/stc8g](power-controller/stc8g/README.md). The code uses 1,577
bytes in R1. The user flashed R1 successfully at 11.998 MHz. It could power on
when the button was held while connecting the battery and could power off, but
failed to start normally from standby. Scope captures and a driver regression
identified an uncleared sleep request that repeatedly reloaded Timer0 before
the first button sample. R3 fixes that defect while retaining low-power STOP
(1,583 bytes). R2 IDLE polling remains a fallback (1,426 bytes) with higher,
unmeasured standby current. Both revisions preserve stcgal's calibrated clock
configuration. R3 also masks stale timer requests during STOP entry and passed
400 simulated shutdown/restart cycles. R3 was subsequently confirmed working
on the installed hardware; see the update below. See
[scope findings](power-controller/stc8g/scope-findings.md). The original TC1
build is unchanged.

## Working hardware and battery correction (2026-10-22)

The user confirmed that the R3 STOP power-controller firmware works after
reinstallation: startup, button forwarding, shutdown and restart all work.
Whole-device switched-off consumption is 0.25 mA. Component calibration
completed and readings appeared plausible.

Latest battery-powered measurements: VCC and AVCC 4.99 V, AREF 4.984 V.
The earlier low supply readings no longer describe the working device.
Measuring PA5 loads the sense circuit: with the DMM attached PA5 was 3.56 V
and the display 3.84 V; removing that probe raised the display to 4.12 V.
Therefore determine battery correction by measuring only the battery leads,
with USB/ISP disconnected and a fresh displayed reading.

| Battery DMM (V) | Original display (V) | Predicted corrected display (V) |
| --- | --- | --- |
| 3.18 | 3.39 | 3.145 |
| 3.78 | 4.02 | 3.775 |
| 3.93 | 4.18 | 3.935 |
| 3.81 | 4.05 | 3.805 |
| 4.12 | 4.39 | 4.145 |
| 3.53 | 3.79 | 3.545 |
| 3.33 | 3.58 | 3.335 |

Mean excess is 245.7 mV. The separate `BOARD=T7` profile changes
`BAT_OFFSET` from 290 mV to 45 mV, reducing displayed and battery-threshold
voltage by 245 mV. Predicted residual errors are -35 to +25 mV on these
samples, before display truncation. This is a battery-only correction;
`UREF_VCC`, component algorithms and calibration EEPROM are unchanged.
It still needs verification after flashing.

The profile also enables the existing `POWER_OFF_TIMEOUT=60`: approximately
60 seconds waiting for input in auto-hold mode. The timer is restarted on
entry to the input wait; tool execution disables it. Continuous probing
retains the existing shutdown after five consecutive empty tests.

Build separately, without replacing root TC1 artifacts:

```sh
python3 tools/build-t7.py -j4
```

Output: `build/t7/ComponentTester-T7.hex`. Program only this AVR flash image
using the existing ISP setup. Do not write the default EEPROM image or
change fuses. U5 needs no further programming. After flashing, check paired
battery/display readings, wait about a minute on a held result for automatic
shutdown, and verify a normal restart.

Validated build: 32,744/32,768 bytes flash, 246 bytes static RAM. Configuration,
HEX bounds/checksums and pixel-rendering checks passed. All existing tools
remain enabled. The short inactivity counter uses one byte for timeouts up
to 127 seconds; longer configured timeouts retain the original two-byte counter.
The icon renderer emits each doubled pixel directly to save flash; its output
is checked by the existing renderer test. T7-only compiler settings provide
the remaining space. The default TC1 profile retains its original battery
offset and disabled inactivity timeout.

## Zener input and external reference

The user identified a 431-marked SOT-23 U6, connected to PA3 / physical pin 34,
measuring 2.499 V. The T7 profile now enables `HW_REF25` with `UREF_25=2499`.
The firmware checks this reference at startup and derives AVCC from it;
the programmed 5.001 V remains the fallback when the reference check fails.
The calibration is limited by the accuracy of the user's DMM.

Traced dedicated ZIF contacts and supply:

- A has 0 ohms to battery negative.
- Transformer -> SS310 rectifier -> two parallel reservoir capacitors ->
  10 kohm (`103`, measured) series current limiter -> K.
- K -> 100 kohm (`01D`) -> PA4 / physical pin 33, with resistance from PA4 to
  ground. The 100 kohm in-circuit reading changes with probe polarity because
  of other circuit paths; it was initially misread as `010`.
- Empty-socket K measured 38.5 V, PA4 measured 3.97 V. The separate 78L05
  regulator input measured 7.8 V.

The profile enables `HW_ZENER` and `ZENER_UNSWITCHED`: the dedicated high-voltage
source already runs with the device on. No boost-control GPIO is driven.
The custom divider uses confirmed `ZENER_R1=100000` and `ZENER_R2=12000`,
matching the earlier in-circuit measurement. The first build provisionally
used 11500 ohms, inferred from 38.5 V / 3.97 V. Zener operation was confirmed,
but five comparisons with a Fluke showed readings consistently 3–5% high.
The 12000-ohm setting lowers the scale by about 3.7%, predicting agreement
within roughly 1% on those samples. The lower resistor's actual marking has
not been confirmed; verify the updated scale after flashing. The previous
11.5 kohm image is retained as `build/t7/ComponentTester-T7-zener-11k5.hex`. Do not connect these high-voltage contacts to normal
probe contacts.

To make space, the T7 stores each distinct 4-byte symbol row once and indexes
it from the original 15 symbols: 1920 bitmap bytes become 1228 bytes. Nothing
is removed from the visible symbol set. `tools/pack-t7-symbols.py` generates
the packed header from the original bitmaps; `--check` verifies it is current.
The production renderer is tested against every original pixel in all 15
symbols at 1x and 2x sizes and two foreground colors. The default TC1 profile
continues using the original uncompressed data.

The new image is `build/t7/ComponentTester-T7.hex`: 32,256/32,768 flash bytes,
246 bytes static RAM. All previous tools, battery correction, onboard IR and
automatic shutdown remain enabled. The previous hardware-confirmed IR build
is preserved as `build/t7/ComponentTester-T7-ir-battery-autooff.hex`.
The user confirmed Zener operation in the menu tool (two short button presses
exit). The updated 12 kohm scale still needs hardware verification.

After updating only AVR flash and preserving EEPROM/fuses, open the Zener
tool. With the K/A contacts empty, compare its reading against the DMM across
K and A. Then test a known Zener using these dedicated contacts: cathode/band
to K, anode to A, and compare its voltage directly with the DMM. The 10 kohm
feed limits available current, so results need not match the nominal Zener
voltage specified at a different test current. Recheck battery display and
normal component readings as the external reference now determines AVCC.

## Earlier investigation notes (superseded where noted above)

### Onboard IR receiver

The user traced the onboard receiver OUT to ATmega324PA TQFP physical pin 12,
which is PD3. The T7 profile now enables `HW_IR_RECEIVER`, disables the
probe-based `SW_IR_RECEIVER`, and sets `IR_PORT/IR_DDR/IR_PIN/IR_DATA` to
`PORTD/DDRD/PIND/PD3`. The TC1 profile retains probe-based IR reception.
The decoder expects an idle-high, active-low demodulated signal and polls
the pin; no interrupt configuration is required.

The IR-enabled image replaces `build/t7/ComponentTester-T7.hex`; it uses
32,716/32,768 flash bytes and passes configuration, flash and renderer checks.
The previously hardware-confirmed battery/auto-off image is retained as
`build/t7/ComponentTester-T7-battery-autooff.hex`. The user confirmed both
battery accuracy and automatic shutdown before the IR change. The new onboard
IR configuration still needs a remote-control test on hardware.

- One identification attempt reached `done` and reported unknown ID `EEA4`,
  then failed because stcgal's unknown-model fallback omits the required
  `iap`, `calibrate`, and `mcs251` fields. This constructor bug was confirmed
  in the installed 1.10 source. `EEA4` is absent from both the installed and
  current upstream model tables; do not alias it to a known chip without
  further evidence. Known entries are F794 (STC8G1K08A-8PIN) and F7A4
  (STC8G1K08-8PIN). The failing attempt did not program flash. Subsequently,
  explicit `-P stc8g` produced a checksum-validated F7A4 identification;
  the earlier EEA4 result is superseded. Original options are recorded in
  [factory-identification.txt](power-controller/stc8g/factory-identification.txt).
- U5 pin 3 has levels consistent with active-high converter enable; direct
  converter routing and ground at pin 4 remain to verify.
- Exact variant confirmed by non-writing ISP identification: STC8G1K08-8PIN.
- Establish the factory protocol with a scope if preserving U5 is preferred.
- Explain the battery display: with the current AVR config (5001 mV assumed
  reference, 290 mV battery correction), the measured PA5/AREF voltages predict
  roughly 3.89 V, not the displayed 5.05 V. Raw ADC diagnostics are needed;
  merely changing the battery correction would conceal the discrepancy.

## Exit first in the T7 main menu

The T7 main menu now lists Exit first and initially selects it. A long press
selects Exit immediately after accidental menu entry; short presses still
advance through the other entries in their previous relative order. Item IDs,
menu length, and the default TC1 menu order are unchanged. The prior confirmed
12 kohm Zener build is saved as
`build/t7/ComponentTester-T7-before-exit-first.hex`.

The adjustment error reported after A6 was resolved by replacing a bad
shorting wire. Its first A2 readings had exceeded the 1.5-ohm acceptance limit;
no calibration thresholds or sampling logic were changed.

## Additional component information

The T7 profile now also enables:

- `SW_C_VLOSS`: capacitor self-discharge voltage loss, displayed as a percentage
  when a positive loss is measured. The measurement is intended for capacitors
  above 50 nF; it is distinct from the existing leakage-current menu tool.
- `SW_HFE_CURRENT`: displays the collector or emitter test current (`I_C` or
  `I_E`) used for the reported BJT gain, depending on test circuit.
- `SW_R_E96_EIA96`: displays matching E96 1% resistor values as EIA-96 SMD codes,
  such as `01D` for 100 kohms. The existing E24 color-band display remains enabled.

These appear in the normal component results, not as new menu entries. All
previous T7 features remain enabled, including Exit first, Zener calibration,
external reference, IR, battery correction and automatic shutdown.

The full build initially exceeded flash by 970 bytes. To retain every feature,
the T7 font now stores row changes using a shared dictionary and compact
character mapping. Bitmap/mapping storage drops from 2160 to 928 bytes;
decoder code reduces the net saving to 1022 bytes in the linked image.
`tools/pack-t7-font.py` generates the packed header from the original font;
`--check` verifies it. The actual decoder and LCD character renderer are tested
against all 119 original glyphs, every one of the 256 character mappings, two
foreground colors, edge positioning and unsupported characters. All glyphs,
including battery icons and special characters, retain their original pixels.
The decoder uses a temporary 16-byte stack buffer. TC1 uses the original font.

The previous confirmed image is saved as
`build/t7/ComponentTester-T7-before-extra-measurements.hex`. The updated image
is `build/t7/ComponentTester-T7.hex`; verify the additional result fields on
hardware after updating flash with calibration EEPROM preserved.

Validated size: 32,716/32,768 flash bytes (52 free), 252 bytes static RAM.
T7 configuration, symbol and font pixel checks pass; the default TC1 build
also passes its configuration and renderer checks with its original features.

## Optional faster display experiment

The working build remains `build/t7/ComponentTester-T7.hex`. A separate
`python3 tools/build-t7.py --fast-display -j4` produces
`build/t7-fast/ComponentTester-T7-fast-display.hex`, selected by

clock-only fill failed to erase on hardware; the revision uses the same word
writer for clearing as for drawing. Hardware verification of this fix is pending.
